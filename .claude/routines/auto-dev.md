#### B. TypeScript type safety improvements

**Hedef:** `any` type kullanımını azaltmak.

```bash
grep -rn ": any" packages --include="*.ts" --include="*.tsx" | wc -l
grep -rn ": any" packages --include="*.ts" --include="*.tsx" | grep -v "\.test\." | head -20
```

**Otomatik düzeltme kuralları:**
- Event handler: `any` → `React.MouseEvent<HTMLButtonElement>` vb.
- Response: `any` → `unknown` (daha güvenli, explicit cast gerektirir)
- Optional field: `any` → `string | undefined` gibi
- Object literal: `any` → `Record<string, unknown>`

**YAPMA:**
- Complex type inference (devam ederse implicit any olabilir)
- Generic type parameter ekleme (breaking)
- Type alias ekleme 5+ dosya ise (refactor gerek)

**Akış:**
1. `any` kullanımları listele
2. Low-risk dönüşümleri tespit et (event handler, simple response)
3. Max 10 dosya/PR
4. `pnpm -w run typecheck` pass zorunlu
5. Branch: `claude/ts-types-YYYY-MM-DD`

#### C. Lint auto-fixes

```bash
pnpm -w run lint --fix 2>&1 | tee /tmp/lint.log
```

ESLint'in `--fix` ile otomatik çözebildikleri:
- Import sıralama
- Unused imports
- Missing/extra semicolons
- Quote style tutarsızlığı
- Trailing whitespace
- `prefer-const`
- `no-unused-vars` (otomatik kaldırma)

**YAPMA:**
- `--fix --unsafe` kullanma (breaking risk)
- Lint rule config'i değiştirme
- Warning'leri `// eslint-disable` ile susturmak

**Akış:**
1. `--fix` ile otomatik düzelt
2. `pnpm -w run lint` tekrar çalıştır, 0 issue olmalı
3. `pnpm -w run test` pass
4. Branch: `claude/lint-autofix-YYYY-MM-DD`

#### D. Master issues reconciliation

Önceki quality-security audit tespiti: "Commit mesajlarında ISS-XXX kapatılmış ama master-issues.json'da hâlâ open."

**Akış:**
```bash
# Son 7 gün commit mesajlarında kapanmış issue'lar
git log --since="7 days ago" --format="%s %b" | grep -oE "(close|closes|closed|fix|fixes|fixed)[s]?:? +ISS-[0-9]+" | sort -u

# master-issues.json'da hâlâ open olanlar
cat .claude/context/master-issues.json | jq '.issues[] | select(.status == "open") | .id'
```

1. Kapanmış issue'ları tespit et
2. `.claude/context/master-issues.json`'da `status: closed`, `closed_at: <date>`, `closed_by_commit: <sha>` ekle
3. Branch: `claude/issues-reconcile-YYYY-MM-DD`
4. Commit: `chore(issues): reconcile closed issues (N items)`

**DİKKAT:** master-issues.json content değişiyor → test gereksiz (JSON sağlam olduğunu `jq .` ile doğrula).

**YAPMA:**

**Vitest pattern:**

import { describe, it, expect } from 'vitest';

**Akış:**

## DEBUG

**`pnpm install` fail:**
- Node version uyuşmazlığı? → log, skip
- Registry unreachable? → retry 1x
- Peer dependency conflict? → log, skip

**`typecheck` fail (routine'in kodundan):**
- Rollback o değişikliği
- Skip o alan
- Log: "TS errors introduced by <area>, reverted"

**`test` fail ama kod değiştirmedin:**
- Flaky test olabilir
- Retry 1x
- Yine fail → skip

**Prisma migration conflict:**
- ASLA otomatik çözme
- Log: "Prisma migration conflict detected, HUMAN REVIEW REQUIRED"
- Skip tüm remaining work
