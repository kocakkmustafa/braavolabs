# Routine Safety Rules — Ortak Güvenlik Kuralları

> Bu dosya 3 projenin autonomous routine'lerinde ortak. Aynı içerik her projeye commit edilir.
> Kaynak prensip: claude-code-safety-net + trailofbits-skills + superpowers

## ASLA YAPILMAYACAKLAR (Hard Constraints)

Bu kurallardan herhangi birini ihlal etmek = routine'in derhal durması + incident log.

### Git operations
- `git push --force` ASLA — force push geçmişi yok eder
- `git push --force-with-lease` ASLA — aynı risk
- `git reset --hard` ASLA — local değişiklikleri yok eder
- `git clean -f` ASLA — untracked dosyaları siler
- `git checkout -- .` ASLA — working directory'yi sıfırlar
- `git rebase` ASLA — history rewrite
- `git commit --amend` (remote'a push sonrası) ASLA
- `git branch -D` ASLA (sadece `-d` safe delete)

### Branch operations
- `main` branch'e DOĞRUDAN commit ASLA
- `develop` branch'e DOĞRUDAN commit ASLA
- `master` branch'e DOĞRUDAN commit ASLA
- Her değişiklik `claude/*` prefix'li yeni branch'te olacak

### File system
- `rm -rf` ASLA (hiçbir path için)
- `rm -rf /` ASLA
- `rm -rf ~` ASLA
- `rm -rf .git` ASLA
- `rm -rf node_modules` → bunun yerine `pnpm install --frozen-lockfile` kullan
- Başka developer'ın untracked dosyalarını silme

### Secrets & credentials
- API key, token, password'leri ASLA log'a, commit'e, PR açıklamasına yazma
- `.env`, `.env.local`, `.env.production` dosyalarını ASLA commit etme
- GitHub Secrets'a routine'den ASLA yazma (sadece okuma varsa kullan)
- Private key (`.pem`, `id_rsa`) içeriğini ASLA okuma/log

### CI/CD & deploy
- `.github/workflows/*.yml` dosyalarını ASLA auto-edit — bu human-only territory
- Production secret'larına touch etme
- Deploy trigger'larını ASLA manuel tetikleme
- `package.json` içindeki `"scripts"` → sadece açıkça belirtilen durumlarda düzenle

### Version changes
- Major version bump ASLA (breaking change riski çok yüksek)
- Sadece patch (`x.y.Z`) ve minor (`x.Y.z`) güncelleme yap
- `engines`, `node`, `pnpm` version gereksinimlerini ASLA değiştirme

### PR operations
- Kendi açtığın PR'ı ASLA merge etme (`gh pr merge` yasak)
- PR'ı `auto-merge`'e ASLA çevirme
- Başkasının (insan) PR'ına ASLA commit ekleme
- Protected branch override girişimi ASLA

### Network & external calls
- External API'lara yük bindiren loop ASLA
- Production database'e DIRECT connection ASLA (okuma bile dahil, read-only olsa dahi)
- Rate-limited service'e 10+ istek/dakika ASLA

### Testing shortcuts
- Test'leri skip etme (`.skip`, `.only`, `xit`) ASLA
- Test suite'i "disable" etme (test runner config) ASLA
- Flaky test'i "fix" etmek için assertion'ı gevşetme ASLA

## HER ZAMAN YAPILACAKLAR (Always)

### Her değişiklik öncesi
- `git status` — tree temiz mi kontrol et
- `git fetch origin` — latest state al
- Eğer dirty tree (uncommitted changes) varsa: **HİÇBİR ŞEY YAPMA, incident log + çık**

### Her branch için
- Feature branch'ten oluştur: `git checkout -b claude/<type>-<description>-YYYY-MM-DD`
- Type'lar: `deps`, `lint`, `a11y`, `l10n`, `test`, `docs`, `security`, `perf`
- İsim kısa olsun, hyphenle ayır, tarih en sonda

### Her değişiklik sonrası
- Test suite çalıştır, hepsi pass etmeli
- Lint çalıştır, yeni uyarı çıkmamalı
- Build çalıştır (eğer build adımı varsa)
- Hepsi pass ettikten sonra commit

### Her commit için
- Conventional Commits formatı:
  - `fix(deps): bump flutter_secure_storage 9.2.2 → 9.2.4`
  - `chore(lint): remove unused imports (12 files)`
  - `feat(a11y): add Semantics labels to settings screen`
  - `test: add tests for date_utils module`
- Commit message İngilizce (international readability)
- Footer'da 🤖 tag: `🤖 Generated by <routine-name>`

### Her PR için
- Title: `[type] Kısa açıklama` formatında
- Body: What / Why / How / Testing / Risk bölümleri
- Label: `claude-auto`, `needs-review` + priority (`P0`/`P1`/`P2`)
- 50+ dosya değişen PR açma (review'a sığmaz) — parçala

### Her run sonunda
- GitHub issue'ya automation-log yaz (title: `🤖 <routine-name> run YYYY-MM-DD`)
- Açılan PR listesi
- Skip edilen alanlar + neden
- Bir sonraki gece için öneriler
- Label: `automation-log`

## DIRTY TREE HANDLING

Eğer `git status --porcelain | wc -l` > 0 ise:

```
🛑 Dirty tree detected on <branch>. 
   <N> uncommitted changes blocking autonomous work.
   Routine exiting without any modifications.
   
   Main developer must:
   1. Review: git status
   2. Commit or stash: git add . && git commit  (or git stash)
   3. Push: git push origin <branch>
```

Sonra **automation-log issue**'una bu mesajı yaz ve **çık**.
ASLA stash'leme, ASLA commit etme. Bunlar human judgment gerektiren kararlar.

## INCIDENT LOGGING

Eğer bir constraint ihlali, unexpected error, veya ambiguous durum olursa:

1. Durdur (başka aksiyon alma)
2. `automation-log` issue'suna incident section ekle:
   ```
   ## 🚨 Incident YYYY-MM-DD HH:MM UTC
   - **What:** kısa açıklama
   - **Context:** hangi aşama/komut
   - **Action taken:** no-op, retry, abort
   - **Recommendation:** main developer için
   ```
3. Routine'den çık
