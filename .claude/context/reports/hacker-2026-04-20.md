### 6. ENCRYPTION_KEY Weakness + Rotation Yok

- **Kategori**: OWASP A02 Cryptographic Failures
- **Dosyalar**:
  - `packages/api/src/lib/encryption.ts:7-14`
  - `.env.example:69` default `ENCRYPTION_KEY=change-me-to-a-random-32-char-key!!!`
- **Aciklama**:
  - `getKey()` `Buffer.from(key.slice(0, 32), "utf8")` — 32 **utf8 character** kesiyor. Ama **AES-256 icin 256-bit (32 byte) key gerekli**, utf8 string (ascii) icin 1 char = 1 byte sadece ASCII aralikta. Non-ASCII char girilirse (turkish chars vb.) `Buffer.from(utf8)` >32 byte olur, `slice(0,32)` eksik byte alir → invalid key derivation.
  - Prod deployment ornek key'i aynen kullanirsa **kurban tenant'in tum API key'leri (HubSpot token, Stripe key, Anthropic key) public deployed key ile encrypt** → GitHub'da veya env dump leak olursa her tenant key'i decrypt edilebilir
  - **Key rotation yok** — `ENCRYPTION_KEY` degistirilirse eski encrypted integrations.credentials decrypt edilemez (`integration/router.ts:201-207`'de catch → "Failed to decrypt credentials — please re-enter"). Production rotation kullaniciya kesinti yaratir.
  - PBKDF2/scrypt KDF yok → env raw key yerine derive edilmeli.
- **Exploit**: Az olasilik ama impact yuksek. Supply-chain veya ops disaster.
- **Cozum**:
  1. `getKey()` icinde raw key yerine scrypt/PBKDF2 ile 32-byte turetim:
     ```ts
     import { scryptSync } from "node:crypto";
     function getKey(): Buffer {
       const key = process.env.ENCRYPTION_KEY;
       const salt = process.env.ENCRYPTION_SALT || "aicos-v1";
       if (!key || key.length < 32) throw new Error(...);
       return scryptSync(key, salt, 32);
     }
     ```
  2. Key rotation plan: `integrations.credentials_kid TEXT` kolonu ekle → ENC_KEY_V1, V2 vs. decrypt fallback. `V2` yayinlandiginda arka plan job eski'leri re-encrypt.
  3. `.env.example`'daki **default key placeholder'i** `"ENCRYPTION_KEY=PLEASE_GENERATE_USING_openssl_rand_hex_32"` gibi `openssl rand` zorunlu olustur, user prod'da degistirmezse throw ekle:
     ```ts
     if (env.NODE_ENV === "production" && env.ENCRYPTION_KEY.includes("change-me")) {
       throw new Error("ENCRYPTION_KEY placeholder detected in production. Generate with: openssl rand -hex 32");
     }
     ```
- **Oncelik**: **HIGH** — 1 gun.

  ```ts
  const sigBuf = Buffer.from(signature);   // ← BURADA: Buffer.from(hex_string, "utf8") → base byte
  const expectedBuf = Buffer.from(expectedSig); // 64 byte (ascii hex chars)
  if (sigBuf.length !== expectedBuf.length || !crypto.timingSafeEqual(sigBuf, expectedBuf))
  ```
  - `timingSafeEqual` OK (constant-time). Length check OK.
  - **Ama**: saldirgan `X-Webhook-Signature: AAAA...` (64 char, rastgele hex) gonderirse length check gecer, timingSafeEqual farkli → reject. Boylece **length info SIZMAZ** - GOOD.
  - Tek zayif: `Buffer.from(signature)` default `"utf8"` kullanir, yani saldirgan signature'ini non-ASCII Unicode ile gonderirse (yabanci script fake length) — pratikte zor, zayif.
  - Replay: timestamp check 5 dakika — OK.
- **Durum**: Guvenli kullanim zaten Faz 17'de yapilmis.
- **Oncelik**: Low — ama `Buffer.from(signature, "hex")` explicit encoding kullanilmali:
  ```ts
  const sigBuf = Buffer.from(signature, "hex");
  const expectedBuf = Buffer.from(expectedSig, "hex");
  ```
- **Oncelik**: Low — 5 dakika.
