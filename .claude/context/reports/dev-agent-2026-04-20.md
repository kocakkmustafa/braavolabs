## KRITIK BULGULAR

### 1. SQL Injection — Memory semantik arama
- **Tur**: **GUVENLIK** — Kritik
- **Dosya**: `packages/memory/src/search.ts:24-29`
- **Sorun**: `searchMemory()` `companyId`, `type`, `status` degerlerini template literal ile WHERE clause'a yerlestiriyor:
  ```ts
  const conditions: string[] = [`mi.company_id = '${companyId}'`];
  if (type) conditions.push(`mi.type = '${type}'`);
  if (status) conditions.push(`mi.status = '${status}'`);
  if (minConfidence > 0) conditions.push(`mi.confidence >= ${minConfidence}`);
  const whereClause = conditions.join(" AND ");
  const results = await prisma.$queryRawUnsafe<...>(`... WHERE ${whereClause} ...`, vecStr, limit);
  ```
  `companyId` auth'tan gelse bile, `type`/`status` bir enum-validation'dan gecmiyorsa (router checking yok) ya da baska bir handler dogrudan cagirirsa injection mumkun. `tool_executor.ts` veya `recall_memory` tool'u `companyId` olarak agent'tan serbest string aliyor.
- **Etki**: Tenant isolation bypass — baska tenantin memory_items'ini okumak mumkun. CRITICAL RULE #10 ("tenant_id filtrelemeli") ihlali.
- **Cozum**: Prisma parametrik placeholder'a gec:
  ```ts
  await prisma.$queryRaw<...>`
    SELECT mi.id, mi.content, ..., 1 - (me.embedding <=> ${vecStr}::vector) AS similarity
    FROM memory_items mi
    JOIN memory_embeddings me ON me.memory_item_id = mi.id
    WHERE mi.company_id = ${companyId}
      ${type ? Prisma.sql`AND mi.type = ${type}::"MemoryType"` : Prisma.empty}
      ${status ? Prisma.sql`AND mi.status = ${status}::"MemoryStatus"` : Prisma.empty}
      ${minConfidence > 0 ? Prisma.sql`AND mi.confidence >= ${minConfidence}` : Prisma.empty}
    ORDER BY me.embedding <=> ${vecStr}::vector
    LIMIT ${limit}
  `;
  ```
- **Tahmini sure**: 1-2 saat. **Delege**: `hacker-agent` taramasinda dogrulanmali.
